## Найденная причина зависаний игры (важно и для обычной сборки пользователя)
UE3 главный поток крутит spin-wait (0x11593600) ожидая поток рендера, а dgVoodoo в потоке рендера вызывает SetWindowPos/ShowWindow на окне игры → кросс-поточный синхронный вызов ждёт главный поток → DEADLOCK. Проявляется при старте/смене фокуса (у пользователя с ReShade висло на загрузке).
Фикс в моде (focus.cpp): хуки SetWindowPos/ShowWindow/MoveWindow → асинхронные (SWP_ASYNCWINDOWPOS / ShowWindowAsync), если вызов из чужого потока. Проверено: 3/3+ запуска без зависаний.

## Адреса / структуры (база 0x10900000)
- FPS cap: float 0x12A03F30 (дефолт 30). Мод держит значение FpsLimit (по умолч. 120). ПРОВЕРЕНО: 120 fps в игре.
- GNames: TArray @0x12B2F0F4; FNameEntry: +0 Index, +8 UTF-16 имя.
- UObject: +0 vtable, +8 flags(qword), +0x10 второй vtable, +0x18 = Index+1 (?). Name/Class не найдены (не нужно пока).
- Камера-актор: vtable 0x1293BEB0. POV (CameraCache/ViewTarget.POV) @ +0x324: TPOV {float X,Y,Z; int Pitch,Yaw,Roll; float FOV}.
- **ACamera::UpdateViewTarget(FTViewTarget& OutVT, float dt) = 0x113A8390** (__thiscall, ret 8), this = camera+0x10, OutVT+8 = TPOV. Хук ПОСЛЕ оригинала, правка OutVT->POV = меняет итоговый вид. ПРОВЕРЕНО скриншотами (fakehead 60 0 → поворот вправо, fakehead 0 30 → вверх, FOV меняется).
- 0x10A96500 — промежуточный FOV-blend камеры (правка выхода НЕ влияет на вид).
- Ввод: XInput (xinput1_3.dll) — прокси. Виртуальный геймпад ВСЕГДА «подключён» (иначе игра стартует в режиме клавиатуры и A в меню не работает). Без фокуса окна UE3 игнорирует ввод → хуки GetForegroundWindow/GetActiveWindow/GetFocus + проглатывание WM_ACTIVATE*/WM_KILLFOCUS.

## Отзыв 4 (в шлеме, ~20:30) — ПЛАН СЛЕДУЮЩЕЙ СЕССИИ (делать по порядку)
Тело и руки появились (скрины: руки и оружие видны, NPC больше не пропадают). Жалобы и решения:

2. **Тело громоздкое, мешает обзору → оставить ноги до пояса, торс невидимым; руки и ноги тоньше (как в VRChat)**: в OnSkelPose масштабировать кости: торс/грудь/плечевые щитки (C_Spine02..03, *ClavRobo*, *ShoulderRobo*, C_Lumbar02Robo*, L/R_Lumbar02Robo*, R/L_Arm01_Clav — проверить именами) → ~0.01 (у детей-рук, которые ведёт IK, свой масштаб не наследовать: IK-кости писать после, со своим масштабом). 3. **Руки не совсем совпадают с контроллерами**: сейчас позиция руки = aim pose (кончик контроллера). Взять grip pose (xr.gripSpace есть в vr.cpp?) для позиции кисти, aim — для направления ствола; добавить смещение кисти в ini (HandOffsetX/Y/Z, см).

Минимум: визуально сдвигать меш пешки под голову (горизонтальное смещение головы в LOCAL × WorldScale → сдвиг всех костей, как в п.1). 5. **Направление ходьбы — по голове, а не по контроллеру**: игра двигает пешку относительно PC.Rotation (= прицел контроллера). В xinput_proxy повернуть левый стик на (aimYaw − headYaw) (yaw прицела и головы — из camera.cpp), чтобы «вперёд» = куда смотрит голова. Опция ini MoveDirection=head/hand.
6. **Транспорт**: в форме машины камеру выше и чуть назад (определить режим машины: другой меш/вьютаргет/скелет — смотреть лог `camera: view target` при трансформации; ini VehicleEyeHeight/VehicleEyeBack).

### 29.10 ~20:25 — НОРМАЛЬНЫЙ VR-РЕЖИМ: оба глаза за один тик + стандартный цикл OpenXR (MockXR проверено, в шлеме НЕТ)
- **Причины «плавающего» стерео (то плоский, то объёмный транспорт) в старом AFR (`StereoPerFrame=0`)**:
  1. PhysX шагает фиксированными шагами `1/60` с (`WorldInfo+0x4C0`): даже при удержании `GDeltaTime=0.001` с на кадре правого глаза аккумулятор PhysX периодически перешагивал порог между глазами и сдвигал машину на ~25 ед. (~12.5 см, ~2× IPD), пока база камеры погони `g_latchBase` оставалась замороженной (`!g_chaseValid`).
  2. Два отдельных вызова `xrLocateViews` с разницей 6–8 мс давали разные предсказания позы головы по Wi-Fi.
  3. `xrWaitFrame`+`xrBeginFrame` вызывались прямо перед `xrEndFrame` в конце `PresentStereo` — каждый кадр рендерился с `predictedDisplayTime` предыдущего кадра.
  4. Прошлая попытка `StereoPerFrame=1` (26.10) вешала хук на `0x1184FA20` (`UAudioDevice::Update`), а не на реальную отрисовку вьюпорта.
- **Архитектурное решение (`StereoPerFrame=1` и `SingleThreadRender=1` по умолчанию)**:
  - **Старт кадра OpenXR в начале тика движка**: хук `appUpdateTimeAndHandleMaxTickRate` (`0x110029B0`, `HookUpdateTime` → `VRBeginTick()`) вызывает `xrWaitFrame` + `xrBeginFrame` + `UpdateInput()` ДО замера `GDeltaTime` движком. Шлем сам задаёт темп тиков (72/80/90 Гц), удержание `GDeltaTime` в `OnFrameDelta` (`0x1100956C`) отключено — UE3 и PhysX идут с естественным `dt` без скачков физики на стенах, задержка ввода уменьшена на 1 тик, импульсы ввода не декрементируются дважды.
  - **Двойной проход рендера из одного состояния мира**: хук реального `DrawViewport(FViewport*)` (`0x11698A90`, `__stdcall`, `ret 4` — вызывается из `UGameEngine::RedrawViewports` `0x11698DDD` и загрузочного `0x115CB48F`). На каждом геймплейном тике один раз вызывается `xrLocateViews` для текущего `predictedDisplayTime` (`VRBeginStereoPair`), в `vr.cpp` сохраняются обе структуры `g_tickEyes[2]`. Проход 1 рисует и презентует левый глаз, Проход 2 — правый глаз из того же мгновения мира, после чего `PresentStereo` отправляет стереопару в `xrEndFrame`. На время стереопроходов у камеры сбрасываются биты `bLockedFOV | bConstrainAspectRatio` (`*(uint32_t*)(cam + 0x1D4) &= ~3u`).
  - **Критичная особенность TWFC (`ATransPlayerController::GetPlayerViewPoint`, `0x10B197C0`)**: при управлении трансформером `ULocalPlayer::CalcSceneView` (`0x1145EE00`) берёт позицию и поворот камеры напрямую из `PlayerController` (`pc + 0xD8..0xEC`), минуя `ACamera::GetCameraViewPoint` (`0x117BACF0`). В `SetCameraView` добавлена запись `Location`+`Rotation` в `pc + 0xD8..0xEC` (без неё второй проход рендерил с позой левого глаза).
  - **Отдельный `FSceneViewState` для правого глаза**: через `AllocateViewState()` (`0x11533290`) выделяется второй `FSceneViewStateInterface*`, подменяемый в `ULocalPlayer->ViewState` (`[lp + 0x74]`, с сохранением `LastViewLocation` `lp + 0x80..0x8B`) на время второго прохода — матрицы motion blur (`PrevViewProjMatrix`) и D3D9 occlusion queries не смешиваются между левым и правым глазом.
  - **Защита от чёрных вспышек на загрузках/переходах**: если начатый в `VRBeginTick` кадр OpenXR не получил нового `Present` (загрузка или окно гистерезиса паузы), `FinishUnsubmittedFrame` повторно отдаёт последний готовый `g_lastProjViews` / `g_lastTheaterQuad`.
  - **IK скелета (`ik.cpp`)**: при `StereoPerFrame=1 && SingleThreadRender=1` отключён AFR-повтор замороженной позы `g_frozen` — поза рук, пояс с гранатами (`PlaceBelt`) и мировые матрицы оружия для двуручного хвата считаются на каждом тике; `viewPos` для `IKSetPawn` центрируется между глазами.
